# 🧊 이유식 큐브

이유식 큐브 재고 관리 + 식단/레시피 추천 웹앱 (2026-02-25생 아기 기준, 설정에서 변경 가능)

## 기능

| # | 기능 | 위치 |
|---|---|---|
| 1 | 큐브 등록 (재료명·분류·만든 날짜·용량·개수), 분류 자동 추정 | 큐브 탭 |
| 2 | 식단 추천 — ⚡ 규칙 기반(오프라인) / ✨ Claude AI. 9개월 미만 점심·저녁, 9개월부터 아침 추가. **매끼 밥, 점심 소고기, 저녁 닭고기 또는 생선** | 식단 탭 |
| 3 | “먹었어요” 누르면 큐브 자동 차감 (되돌리기 가능), 재고 대시보드 | 홈 / 식단 탭 |
| 4 | 9개월부터 큐브 조합 레시피 추천 (기본 레시피 + AI), 만들면 재고 차감 | 레시피 탭 |
| 5 | 소비기한 = 만든 날 포함 14일. D-day 표시, 임박·초과·소진 불가 예상 알림 | 홈 / 큐브 탭 |
| 6 | 밥·소고기·닭고기(+생선) 소진 예상일과 “새로 만들기 권장일” | 홈 |

### 추천 규칙과 이유 (앱 식단 탭 “왜 이렇게 추천하나요?”에도 표시)
**⚡ 자동 추천 (규칙 기반)** — API 키·인터넷 없이 항상 같은 기준, 재고와 정확히 일치
| 규칙 | 이유 |
|---|---|
| 매끼 밥 | 탄수화물은 주 에너지원 → 모든 끼니의 기본 |
| 점심 소고기 | 6개월 무렵 체내 철분 감소 → 흡수 좋은 헴철을 매일, 낮에 먹여 반응 관찰 |
| 저녁 닭고기/생선 | 단백질 다양화(생선 DHA), 전날과 번갈아, 2일 내 기한 임박한 쪽 우선 |
| 채소 2종 | 비타민·식이섬유, 다양한 맛 노출, 같은 날 앞 끼니와 다른 채소 우선 |
| 소비기한 임박 순(FEFO) | 14일 원칙 준수, 폐기 최소화. 기한 지난 큐브는 절대 사용 안 함 |
| 9개월부터 아침 추가 | 후기 이유식은 하루 3끼가 일반적 |
| 생선 주 2회 | 최근 6일 저녁 생선 2회 미만이면 생선 우선 (DHA·비타민D) |

**채소 선택 우선순위 (위가 항상 이김, `web/js/nutrition.js`)**
1. **음식 궁합** — 나쁜 궁합(예: 소고기+고구마, 시금치+두부)은 기한이 임박해도 절대 같은 끼니에 넣지 않음. 좋은 궁합이 있는 재료를 우선. 궁합표는 설정 → 🤝 음식 궁합에서 편집
2. **영양 보완** — 철분+비타민C, 베타카로틴+지방, 비타민D+칼슘, 색 다양성, 하루 부족 영양 보충, 반복 피하기
3. **소비기한** — 위 두 조건이 같을 때만 기한 임박 큐브 우선

AI 추천에도 같은 궁합표를 절대 규칙으로 전달하고, 결과에 나쁜 궁합이 있으면 앱이 해당 채소를 빼고 알려줍니다.

재료 영양 DB에 약 45종이 등록되어 있고, 식단마다 “하루 영양 체크”(단백질·철분·비타민C·베타카로틴·칼슘·DHA·식이섬유)를 표시합니다.

각 끼니에 💡로 그 끼니의 선택 이유(임박 큐브, 번갈아, 재고 부족 등)를 표시합니다.

**✨ AI 추천 (Claude / Gemini)** — 같은 규칙을 AI에게 주고 맛 궁합·영양 균형·유연한 수량 조정을 맡김
- 실제 큐브 ID만 고르도록 JSON 스키마로 형식 강제
- 결과를 앱이 다시 검사해 기한·재고·필수 규칙 위반을 자동 보정하고 보정 내역 표시
- 끼니별 선택 이유 + 전체 요약 제공

소진 예측은 현재 재고로 자동 추천 식단을 45일 시뮬레이션해서 계산합니다.

## 데이터
- 브라우저 localStorage에 저장. 설정 → 내보내기/가져오기로 백업·기기 이동
- Claude API 키는 해당 기기에만 저장되며 백업 파일에 포함되지 않음

### 가족 공유 (Firebase)
- 구글 로그인 후 “공유 공간”을 만들고 초대 링크로 가족이 참여 → 모든 기기 실시간 동기화
- Firestore `households/{초대코드}` 문서 하나에 앱 상태 전체를 저장 (마지막 저장 우선)
- 오프라인에서 바꾼 내용은 다시 연결되면 올라감
- 설정: `web/js/firebase-config.js`에 웹앱 설정값, Firestore 규칙은 `firestore.rules` 내용을 콘솔에 붙여넣기
- Authentication → 승인된 도메인에 `suitable8111.github.io` 추가 필요

## 개발

```bash
npm test          # 로직 단위 테스트
node scripts/serve.mjs   # http://localhost:5173 미리보기
```

```
web/            ← 배포되는 정적 사이트
  index.html
  css/style.css
  js/logic.js   ← 날짜·소비기한·식단 배정·소진 예측·레시피 (순수 함수)
  js/store.js   ← localStorage
  js/ai.js      ← Claude API (structured output)
  js/app.js     ← 화면
tests/          ← node --test
.github/workflows/deploy.yml  ← main push 시 테스트 후 GitHub Pages 배포
```

## 배포 (GitHub Pages)
1. GitHub에서 새 저장소 생성 후 push
2. 저장소 **Settings → Pages → Build and deployment → Source: GitHub Actions** 선택
3. 이후 `main`에 push할 때마다 테스트 → 자동 배포
